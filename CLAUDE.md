# Club der Fettsäcke – Projektkontext

Abnehm-Wettbewerb unter Freunden (Robbi, Siggi, Julian; weitere können jederzeit einsteigen). Problem vorher: Wetten schliefen nach ~2 Wochen ein. Ziel: ein faires, kompetitives System, das dranhält. Sprache der App und der Kommunikation: **Deutsch**.

## Tech-Stack
- **Die App besteht aus drei Dateien, kein Build, keine Libraries außer Firebase:** `index.html` (nur die Hülle), `style.css` (komplettes Design), `app.js` (ES-Modul: CONFIG, Logik, Datenschicht, UI). Daneben nur statische Dateien: `manifest.json`, `icons/`, `fonts/`, `firebase-messaging-sw.js`.
- **Tests** in `tests/` (nur zum Entwickeln, eigenes `package.json`, siehe `tests/README.md`): `npm test` = Logik aus app.js + `firestore.rules` im Emulator (TESTMODE false und true) + `reminders/send.mjs` mit gestellter Uhr; `npm run ui` = Playwright-Screenshots; `npm run forms` = Abläufe im Browser (Formulare beim Neuzeichnen, Extra-Habits, Foto-Beweis, Erklärungen); `npm run docs` = README-Tabellen aus CONFIG + Screenshots. Nach Änderungen an Regeln, Punkten oder Zeitfenstern dort Fälle ergänzen und laufen lassen.
- **Cache:** `index.html` bindet `style.css?v=N` und `app.js?v=N` ein. Nach Änderungen an CSS/JS die Nummer hochzählen (GitHub Pages cacht 10 Min.).
- **Lokal testen** geht nur über einen Server (ES-Module laden nicht per `file://`): `python3 -m http.server`, dann `index.html?demo`. `?demo` erzwingt den Demo-Modus trotz Firebase-Config, `?bots=18` simuliert bis zu 20 Spieler, `#ich`/`#ranking` usw. öffnet direkt einen Tab, `?now=…` stellt die Zeit.
- **Firebase** (Spark-Plan, kostenlos): Google-Login (Authentication) + Firestore (Region europe-west3) + Cloud Messaging (Push). SDK per CDN: `https://www.gstatic.com/firebasejs/10.14.1/`.
- **Hosting:** GitHub Pages → `https://rob17020.github.io/fettsaecke/` (Repo `fettsaecke`, Branch `main`, root). In Firebase Auth ist `rob17020.github.io` als autorisierte Domain eingetragen.
- **`firestore.rules`**: Sicherheitsregeln, manuell in der Firebase-Konsole einfügen + veröffentlichen.
- Firebase-Projekt: `club-der-fettsaecke`. Die Config steht in `CONFIG.firebase` (apiKey ist öffentlich, Schutz läuft über die Regeln). **Dieselbe Config steht auch in `firebase-messaging-sw.js`.**
- **Erinnerungen:** GitHub Actions (`.github/workflows/reminders.yml`, Cron in UTC doppelt für Sommer-/Winterzeit) startet `reminders/send.mjs` (Node + firebase-admin). Service-Account nur als GitHub-Secret `FIREBASE_SERVICE_ACCOUNT`, nie committen. Einrichtung: `README.md`.
- **Backup:** gleicher Workflow, Job `backup` (Sonntag 22:30 UTC oder per Hand, Art `backup`): `reminders/backup.mjs` exportiert alle Sammlungen inkl. Unter-Sammlungen in eine Datei, gzip + AES-256-GCM mit Secret `BACKUP_PASSPHRASE` (Pflicht, ohne bricht der Job ab), Artefakt 90 Tage. Grund für die Verschlüsselung: Artefakte öffentlicher Repos kann jeder angemeldete GitHub-Nutzer laden, und die Datei enthält die privaten kg-Werte. `reminders/restore.mjs` spielt in eine leere Datenbank zurück (`--dry-run`, `--force`). Format in `reminders/backup-format.mjs`. Backups nie committen (`.gitignore`: `backup/`, `*.fsbak`). Beide Skripte laufen mit `FIRESTORE_EMULATOR_HOST` auch gegen den Emulator.
- Schrift: Schibsted Grotesk, lokal in `fonts/` (OFL), kein Google-Fonts-Request.
- **README.md** ist die GitHub-Seite (deutsch): Tabellen zu Punkten/Geld und CONFIG stehen zwischen `<!-- CONFIG:… -->` und werden mit `cd tests && npm run docs -- --tables` aus `CONFIG` erzeugt (nie von Hand ändern), Screenshots in `docs/screenshots/` mit `npm run docs` (Demo, neutrale Namen Alex/Kai/Mo, keine echten Daten). Ausführliche Einrichtung in `docs/SETUP.md`. Code unter MIT (`LICENSE`), Schrift OFL.
- Entwickelt wird auf Pop!_OS (COSMIC) mit VSCodium.

## Wichtige Schalter / Konfiguration
Alles oben in `app.js` unter `CONFIG`:
- `firebase: null` (oder `?demo` in der URL) → **Demo-Modus** (lokale Daten, simulierte Bots Siggi & Julian inkl. Team-Monat-Vorschlägen/Beiträgen und „zuletzt aktiv“, Zeitsteuerung im Banner bzw. per `?now=`; mit `?bots=N` weitere Bots).
- `testMode: true` → Zeit in Prod per URL simulierbar (`?now=2026-11-30T09:00`). **Vor dem Saisonstart auf `false`!** Im Test-/Demomodus darf ein Altspieler ohne Ziel sein Ziel auch nach dem Startgewicht einmal setzen.
- Punkte: `weighPerTenth: 3`, `weighMaxTenths: 10` (max. 30, ca. 60 % einer realistischen Woche), `habitMaxPts: 4` (pro Habit, max. 12/Woche), `challengePts: 4`, `taskPts: 10`, `teamPts: 5`. Keine Zahlen fest in UI-Texten, immer aus CONFIG.
- Geld: `einsatz: 20`, `strafe: 5` (verpasstes Wiegen), `habitFee: 1` (Woche ohne alle 3 Wochenziele), `loserFee: 0.5`. Auch in `SEASON` in `reminders/send.mjs` (strafe, habitFee). `eur()` zeigt Cent nur bei Bedarf (20 €, 0,50 €).
- `pauseWeeks: 2` (Pausenwochen pro Saison), `holdBand: 1` (Haltephase: erlaubte Abweichung vom Ziel in Prozentpunkten).
- `weighStartHour: 3` / `deadlineHour: 14` (Wiegefenster). `teamDraw: 3` (gezogene Vorschläge), `activeEveryMin: 10` (lastActive höchstens alle 10 Min. schreiben), `vapidKey` (Web-Push-Schlüssel; leer = Erinnerungen aus).
- In `firestore.rules`: `TESTMODE()` → `true` schaltet die Zeitfenster-Prüfungen ab (Wiegen, Haken, Team, Habits ändern, Pause). **Vor dem Saisonstart auf `false`!**
- **Admins / Nachtrag:** `CONFIG.adminUids` und `ADMINS()` in den Regeln (gleiche uids; die eigene uid steht im Profil unter Konto). Admins sehen im Profil „Admin: Nachtrag erlauben“: Spieler + Wiegen (Slot) + Frist → schreibt `lateUntil` (Zeitstempel, höchstens `lateMaxDays` voraus) und `lateSlot` aufs Spieler-Dokument; hat der Spieler noch kein Startgewicht, auch `joinedSlot = lateSlot`. Bis `lateUntil` darf er das Wiegen für `lateSlot` außerhalb des Fensters schreiben (Regeln `lateOk`), die Wiege-Karte zeigt „Nachtrag erlaubt bis …“, und der automatische Start-Verschieber pausiert (`lateOpen()`, Regeln `lateActive`). Nur Admins schreiben diese Felder (`adminLateOk`). Im Demo ist jeder Admin.
- `INVITE()` in den Regeln = Einladungscode für die Registrierung. **Im Repo steht nur ein Platzhalter, der echte Code nur in der Firebase-Konsole** (Repo ist öffentlich). Codes, die früher einmal im Repo standen (Git-Historie), nie wieder verwenden.
- `START_MS` in den Regeln (1795388400000 = Mo 23.11.2026 00:00 MEZ) muss zu `CONFIG.start` passen, ebenso die festen Zahlen dort: `24` (Wochen), `4`/`28` (Wochen/Tage pro Etappe, Team-Monat, Habits ändern), `2` (Pausenwochen), `1` (Ziel-Band beim Ausstieg), Ziel `1–40` %, Wochenziel `1–7`, Wiegefenster ab 2 Std. MEZ, Wiegeschluss `CLOSE(w)` = 14 Uhr MEZ + 5 Min. (im Sommer 15:05 Ortszeit), Nachtragen/Bestätigen `3 * DAY()` (2 Tage). `SEASON` in `reminders/send.mjs` ebenfalls (inkl. `holdBand`, Strafen).
- Vor dem Start: alle Test-Sammlungen in Firestore löschen (inkl. `teamideas`, `teamlogs`, `reminderRuns`; alte `teamgoals` ganz löschen). Secret `BACKUP_PASSPHRASE` anlegen.

## Spielregeln (aktueller Stand)
- **Saison:** 24 Wochen ab Mo 23.11.2026, 6 Etappen à 4 Wochen. Alles in **Prozent vom eigenen Startgewicht** → fair für jede Größe. „Woche w“ = Haken Mo–So von Woche w + Wiegen am Montag danach (Slot w).
- **Wiegen:** jeden Montag 3–14 Uhr (Startgewicht am ersten Montag). Waage-Punkte: **3 Punkte pro 0,1 %** unter dem bisherigen Tiefstwert, max. 30/Woche (= 1 %, gegen Crash-Diäten). Zunehmen kostet nichts, Punkte gibt's erst wieder unter dem alten Tiefstwert. Verpasst = 0 Punkte + 5 €.
- **Habits:** jeder wählt 3 eigene mit **Wochenziel 1–7×** (`habits: [{name, target}]`, alte Text-Einträge gelten als 7×). Abgehakt wird pro Tag, im Raster steht „2/4“ pro Zeile (grün geschafft, orange nicht mehr erreichbar). Punkte pro Habit = `round(habitMaxPts * min(erledigt, Ziel) / Ziel)`, also max. 4 egal wie hoch das Ziel ist. Bis zu 2 Tage nachtragen, Tage der Vorwoche aber nur bis Montag 14 Uhr (`dayOpen(d)`), dann ist die Woche abgeschlossen (`weekFinal(w)` = Wiegeschluss Slot w). Ab da stehen Punkte, Wochenletzter und Habit-Strafe fest, auch Woche 24 mit dem Saisonende. Hinweise im Raster: am Wochenende und Montagmorgen „nur bis Mo 14:00“, danach „abgeschlossen“. Ändern nur vor dem Start, in der 1. Woche jeder Etappe und vor dem eigenen Start (Spätstarter); gespeichert pro Etappe in `habitSets`, damit alte Wochen ihre alten Ziele behalten (`habitsFor(p, w)`). Zu leichte Habits: Gruppen-Veto (steht in den Regeln). **Eine Woche ohne alle 3 Wochenziele kostet 1 €**, sobald sie abgeschlossen ist (`missedHabitWeeks`, `weekFinal()`); auf Heute warnt montags bis 14 Uhr eine Zeile.
- **Wochen-Challenge (max. 4 P.):** Montag nach dem Wiegen darf der **Wochenletzte 12 Std. lang** wählen, danach jeder. Täglich (1 P./Tag, max. 4) oder 1×/2× pro Woche (4 bzw. je 2 P.). Abhaken in der „Challenge:“-Zeile im Habit-Raster (`habitlogs.done[3]`).
- **Extra-Aufgaben (Komfortzone):** jeder stellt **1 Aufgabe pro Etappe**, alle dürfen jede machen, +10 P., zählt erst nach Bestätigung durch jemand anderen. **Melden nur mit Foto** („Erledigt melden“ → Kamera oder Galerie + Notiz ≤ 140): `compressImage()` verkleinert im Browser auf max. 1080 px (WebP, Safari JPEG, Qualität 0,7 abwärts, Ziel < 200.000 Zeichen, hart < 400.000 wie in den Regeln; Metadaten fallen weg). Andere öffnen die Meldung („X prüfen“, auch über die Bestätigen-Karte auf Heute) und **bestätigen** oder **lehnen ab** (Grund optional); abgelehnt → „Neu melden“ mit neuem Foto. Fotos werden nicht abonniert, sondern erst beim Ansehen per `getDoc` geladen (`DB.loadProof`, Cache `PROOF`, Objekt-URLs, `hydrateProofs()` nach jedem Rendern). Galerie „Beweisfotos · Etappe e“ unten in der Karte (lädt beim Aufklappen), Großansicht als Overlay `photo`. Demo: Bots haben erzeugte Platzhalterbilder (`demoProof`).
- **Team-Monat (+5 P. pro Etappe):** jeder schlägt pro Etappe **ein Ziel pro Person** vor (`sum`/`count`; Satz pro Tag/Woche/Monat). Vorschläge für Etappe e ab Beginn von e−1 bis zur Ziehung am ersten Montag von e um 14 Uhr (`drawTime()`). Gezogen werden 3, deterministisch im Client (`drawIdeas()`). Teamziel = Satz pro Woche × Spielerwochen (Spätstarter ab Start, ohne Pausenwochen, Ausgestiegene bis zum Ausstieg; `teamMonth()`). Sind am Ende **alle** Ziele erreicht, bekommt jeder mit Eintrag `teamPts`, sonst niemand. Zählt in Etappen-/Gesamtwertung, nicht in der Wochenwertung.
- **Persönliches Ziel:** Eingabe per Drehrad (`goalPicker`, Zustand in `DIAL`): ungefähres Gewicht + Zielgewicht in 0,5-kg-Schritten, Prozent rechnet die App. Privat gespeichert als `estKg`/`targetKg` in `players/{uid}/private/weights` (`DB.savePlan`). Beim ersten Startgewicht rechnet der weigh-Handler `maxLossPct` aus Startgewicht und `targetKg` neu (selber Batch, danach fest). Öffentlich bleibt nur `maxLossPct` (1–40 % vom Startgewicht) auf dem Spieler-Dokument (öffentlich, weil alle Clients Haltephase/Ausstieg rechnen). Beim Beitreten angegeben, bis zum Startgewicht änderbar (fehlt es, fragt die Startgewicht-Karte und schreibt es im selben Batch), danach fest (Regeln). Heute: Balken „x,x % von y %“, Tab Ich: Ring mit kg-Umrechnung nur für einen selbst. `goalWeek` = erstes Wiegen mit lossPct ≥ Ziel, Meilenstein „Ziel erreicht“, Konfetti. Bis dahin zählt alles normal. Das alte private Zielgewicht (`goalKg`) wird nicht mehr benutzt.
- **Haltephase** (Ziel erreicht, bleibt dabei): ab der Woche nach `goalWeek` läuft alles normal weiter (Habits mit Strafe und Erinnerungen, Challenge, Streak). Einziger Unterschied: Waage = volle Punkte, solange `lossPct >= Ziel − holdBand`, sonst 0. Kein Bonus mehr (Nov 2026 geändert).
- **Ausstieg** (Ziel erreicht, geht): Knopf „Ziel erreicht – aussteigen“ mit Bestätigungsdialog (`canExit()`: Ziel war erreicht und das **aktuelle** Wiegen liegt im Band; `exitSlot()`: montags vor 14 Uhr das heutige, sonst das vom letzten Montag, Pausenwochen übersprungen; fehlt es, steht statt des Knopfs ein Hinweis. Sonst fielen mit einem alten `finishedWeek` die Strafen danach weg, die Regeln prüfen es auch). Setzt `status: 'finished'`, `finishedWeek` (= `exitSlot()`), `finishedAt` (einmalig, Regeln). Danach keine Punkte, Strafen, Erinnerungen; raus aus Wochen- und Etappenranking (abgeschlossene Etappen bleiben), Wochenletzter-Rechnung, Aufgabenzahl. Kasse: „Einsatz zurück“, Topf sinkt, frühere Strafen bleiben. Gesamt: nie in der Wertung (`rankTotal()` filtert sie, auch bei Ausstieg am letzten Montag), sondern eigener Abschnitt „Ziel erreicht“ mit eingefrorenem Ergebnis (`frozenLine()`: „−15,2 % · Ziel nach 18 Wochen“). Ausgestiegene können nur noch lesen (Regeln: `notFinished()`).
- **Pause:** bis zu `pauseWeeks` (2) Wochen pro Saison, im Profil. Laufende Woche bis Mittwoch 23:59 (`pauseDeadline()`), spätere jederzeit; zurücknehmen nur vor Wochenbeginn. Pausierte Woche w (Haken Mo–So + Wiegen am Montag danach): keine Punkte, kein verpasstes Wiegen, keine Habit-Strafe, nicht im Wochenranking/Wochenletzter, keine Erinnerungen, Streak bleibt stehen. Das nächste Wiegen vergleicht mit dem Tiefstwert (Wiegen in der Pause zählt nicht dazu). „Pause“ im Ranking, Restwochen im Profil.
- **Streak (keine Punkte):** **Wochen** am Stück mit allen 3 Wochenzielen (Challenge zählt nicht). Laufende Woche zählt erst, wenn geschafft, bricht aber nicht; Pause und Haltephase brechen nicht. **1 Joker pro Etappe** rettet die erste verpasste Woche, in der gerade eine Streak läuft (`streakOf()`).
- **Meilensteine:** Ziel erreicht, −2/−5/−7,5/−10 % (bester Wert), 4/10/20 Wochen ohne verpasstes Wiegen (Pausen zählen nicht als verpasst), Streak 4/12 Wochen. Klein im Ranking, im Tab Ich, einmaliger Toast (gesehen-Liste `cdf-ms-<uid>`).
- **Einführung:** nach dem Beitreten (und für alle ohne `onboardingDone`) 3 Screens aus den HELP-Texten: Punkte (`HELP.points` + Beispielwoche als Balken, `exWeek()`), Wiegen (`HELP.weigh`, `HELP.goal`), Kasse (`HELP.pot`). Überspringen oder „Los geht's“ setzt `onboardingDone`; Regeln → „Einführung nochmal ansehen“.
- **Schlaf:** Haken zwischen 1 und 5 Uhr → Toast „Geh schlafen. Schlaf ist auch ein Habit.“
- **Liveticker (Heute):** nur im Client aus `weighins` (inkl. „Ziel erreicht“), `habitlogs` (geschaffte Wochenziele, Zeit = letzte Änderung des Tages, an dem das Ziel erreicht wurde), `taskDone`, `weekly`, `teamideas`, Team-Monat und Ausstiegen (`finishedAt`). Letzte 14 Tage, neue Einträge gleiten herein (`FEED.seen`). Ab 3 Spalten (Desktop) als schmale Kopfzeile über dem Dashboard (`feedStrip()`, 10 Einträge, „Alle“ öffnet `feedHtml` als Overlay), die Ticker-Karte ist dort ausgeblendet und das Dashboard hat 3 Spalten mit breiter Habits-Mitte. Darunter: Karte, Tablet 5, Handy 3.
- **Wochenletzter-Karte (Heute):** von Montag 14 Uhr bis zum nächsten Wiegefenster, pulsiert blutorange.
- **Saisonrückblick (Wrapped):** öffnet sich einmal automatisch nach Saisonende (`cdf-wrapped-<uid>`), nicht für Ausgestiegene. Zeigt % seit Start, Platz, längste Streak (Wochen), Strafen, Wochensiege, Nemesis. Keine kg-Werte.
- **Zuletzt aktiv:** „heute aktiv“ / „gestern aktiv“ / „seit X Tagen still“ (ab 2 Tagen rot) im Ranking. `lastActive` wird beim Öffnen, beim Zurückkehren in die App (`visibilitychange`) und nach eigenen Schreibvorgängen gesetzt, höchstens alle 10 Min. (`DB.touch`). Verglichen wird mit der echten Uhrzeit, nicht mit `?now=`.
- **Topf-Karte (Heute):** große Zahl, zählt vom zuletzt gesehenen Stand hoch (`cdf-pot-<uid>`), Balken nach Einsätzen/Strafarten, wer gerade vorn liegt, eigener Anteil. Zweimal im HTML (`p1` in Pane a bis 2 Spalten, `pn` oben in Pane c ab 3 Spalten).
- **Ring-Animationen:** `ringSvg(..., key)` merkt sich Werte in `RING`; Änderung = Ring läuft vom alten Wert, voll = Aufblähen + Funken (`flushRingFx`), alle voll = Leuchten + Toast. Ist der Ring nicht im Bild (Handy), wartet die Animation bis er hineinscrollt (`hold`, IntersectionObserver, max. 1 Min.). Mini-Ring im Kopf der Habit-Karte, „1/1“ springt, wenn ein Wochenziel erreicht ist.
- **Montag:** Ist Wiegen fällig, steht die Wiege-Karte vor dem Liveticker (`.dash.wdue`).
- **Challenges auf Heute (`chNudgeCard`, Pane a nach der Wiege-Karte):** neu seit dem letzten Mal (Extra-Aufgaben der laufenden Etappe, Team-Vorschläge der nächsten Ziehung, Wochen-Challenge dieser Woche, jeweils von anderen; gesehen-Liste `cdf-chseen-<uid>`, Challenges-Tab, „Zu den Challenges“ und „Gesehen“ markieren alles), eigene Aufgabe fehlt (direkt dort stellen, gleiche ids wie im Tab: `tText`/`addTask`), Team-Vorschlag fehlt (Ziehung in < 7 Tagen), offene Aufgaben. Ohne Inhalt keine Karte. Neue Extra-Aufgaben stehen auch im Liveticker.
- **Hinweis oben ohne Push (`newsHint`, nach dem Banner, alle Tabs außer Challenges):** ist Push nicht an (`pushInfo() !== 'on'`, also auch Demo), steht das Neueste aus `chItems()` als schmale cyan Leiste oben (+N weitere, Ansehen, ×=gesehen); sonst „Deine Aufgabe fehlt“ (ab Etappentag 2) bzw. „Team-Vorschlag fehlt“ (Ziehung < 3 Tage), × blendet das für heute aus (`cdf-nhint-<uid>`). Die Challenges-Karte auf Heute listet Neues dann nicht noch einmal.
- **Habits der anderen (`othersHabitsCard`):** alle aktiven Mitspieler mit ihren 3 Habits, Challenge und Extras für die Woche des eigenen Rasters (Punkte pro Woche, Streak, 7 Tagespunkte, gestrichelt = wartet auf Bestätigung). Zweimal im HTML: `ob` unter Raster/Heatmap (bis 3 Spalten), `oa` links in Pane a (4 Spalten). Auf-/zuklappen pro Spieler (`UI.ohClosed`, ab 4 Mitspielern zu).
- **Erinnerungstexte:** `weighMsg`/`habitsMsg` in `reminders/send.mjs`, mehrere Varianten, gewählt per Hash aus uid + Art + Datum (`pick`), täglich wechselnd. Wiegen nennt, wer schon gewogen hat; Habits werden zum Sonntag hin dringlicher.
- **Erklärungen („Was bedeutet das?“):** alle Erklärtexte in **einem** Objekt `HELP = { key: () => html }` (Titel in `HELP_T`), Zahlen nur aus CONFIG, je 2–5 Sätze + ein Beispiel mit echten Zahlen (`hx()`). Schlüssel: points, weigh, cap, habits, confirm, extras, weekly, tasks, team, goal, hold, exit, pause, streak, ms, pot, join, push, late. `helpBtn(k)` = kleiner ?-Knopf (aria-label „Erklärung: …“), öffnet auf dem Desktop ein Popover am Knopf, sonst ein Bottom Sheet (`openHelp`, eigene Ebene `#help` außerhalb von `#app`/`#modal`, Escape/Klick daneben schließt, Fokus zurück). Der Regeln-Tab, die Einführung und „So läuft's“ in den Challenges-Karten zeigen dieselben HELP-Texte. Neue Regel = HELP-Eintrag ändern, dann stimmt es überall; `tests/forms.mjs` prüft 2–5 Sätze + Beispiel mit Zahl.
- **Challenges-Tab:** Jede Karte (Extra-Aufgaben, Team-Monat, Wochen-Challenges) erklärt sich selbst: ein Satz plus aufklappbar „So läuft's“ (`explain(key, intro, HELP.x())`). Offen, bis man es zuklappt (`cdf-expl-closed`).
- **Anmelden/Beitreten:** `.lgrid` (max. 1240 px, mittig): Hero bzw. Formular, 4 Bausteine (`howTiles()`), Regeln als Akkordeon (`viewRegeln(true)`).
- **Neuigkeiten-Push (`--kind=news`, Cron alle 30 Min. :15/:45, sendet 8–22 Uhr Berlin):** neue `tasks`/`teamideas`/`weekly` seit dem letzten Lauf (`ts`, Stand + IDs der letzten 2 Tage in `reminderRuns/news_state`, 10 Min. Überlappung; erster Lauf merkt nur) an alle Nicht-Ausgestiegenen außer dem Ersteller, mehrere in einer Nachricht (`newsMsg`), mit „Deine Aufgabe/dein Vorschlag fehlt noch“. Um 18 Uhr zusätzlich `nudgeMsg`: eigene Aufgabe fehlt an Etappentag 2/6/13/20, Team-Vorschlag 6/2/1 Tag vor der Ziehung (einmal pro Tag, `reminderRuns/nudge_{datum}`). `SEASON.taskPts` muss zu CONFIG passen.
- **Erinnerungen (Push):** Mo 8:00 „Wiegen bis 14 Uhr“ nur an wer noch nicht gewogen hat; täglich 21:00 „Habits noch offen“ mit Stand der Woche („Kochen 2/4“) für Habits, deren Ziel offen ist und die heute noch nicht abgehakt sind. Haken mit „Gruppe bestätigt“ zählen dort wie in der App erst mit `habitok`. Nicht in Pausenwochen und nach dem Ausstieg; in der Haltephase beide. Wer sein Startgewicht verpasst hat, bekommt am nächsten Montag eine neue Start-Erinnerung (die App verschiebt den Start beim Öffnen), außer am letzten Montag. Opt-in im Profil. iPhone nur als installierte App (ab iOS 16.4).
- **Geld:** 20 € Einsatz + 5 € pro verpasstem Wiegen + 1 € pro Woche ohne alle 3 Wochenziele + **0,50 € für den Wochenletzten** (nur wenn nicht alle gleich viele Punkte haben). Ausstieg: Einsatz zurück. Übersicht unter Ranking → Kasse, pro Etappe. Der Gesamtsieger kassiert den Topf.
- **Spätere Einsteiger:** starten am nächsten Montag. Verpasst jemand sein Startgewicht, wird er automatisch auf den nächsten Montag verschoben (erst wenn alle Daten geladen sind, `S.synced`). Mit Firebase zählt dafür die echte Uhrzeit, nicht `?now=` (sonst würde eine simulierte Zeit `joinedSlot` dauerhaft verschieben).
- **Privatsphäre:** Andere sehen nur Prozente (auch das Ziel), die kg-Werte liegen in `players/{uid}/private/weights` (nur für den Besitzer lesbar).

## Datenmodell (Firestore)
- `players/{uid}`: lateUntil + lateSlot (Admin-Nachtrag, optional), name, habits `[{name, target}]` (3; alt: Text), habitSets `{ <Etappe>: [{name, target}] }`, maxLossPct (Ziel in %), pausedWeeks `[Woche]`, status `'finished'` + finishedWeek + finishedAt (Ausstieg), onboardingDone, joinedSlot, joinedAt, invite, lastActive (Server-Zeit, gedrosselt)
- `players/{uid}/private/weights`: `{ slots: { <slot>: kg }, estKg, targetKg }` (nur für den Besitzer; alte Felder `goalKg`/`goal` werden ignoriert)
- `players/{uid}/private/tokens`: `{ tokens: { <fcmToken>: { ts, ua } } }` (Push-Geräte, nur Besitzer + Admin-Skript)
- `weighins/{uid}_{slot}`: uid, slot, lossPct, ts (slot 0 = Start, slot k schließt Woche k ab)
- `habitlogs/{uid}_{day}`: uid, day (Tage seit Start), done[4] (3 Habits + Challenge), extra[≤5] (Extra-Habits), ts (letzte Änderung, nur für den Liveticker)
- `habitproofs/{uid}_{day}_{key}`: Beweisfoto zu einem Haken mit „Gruppe bestätigt“ (uid, day, key, img < 400.000 Zeichen, w, h, ts Serverzeit). Nur eigene, gleiches Zeitfenster wie Abhaken; Löschen (Haken zurück) über die ID, auch wenn es keins gibt. Nicht abonniert, nur beim Ansehen geladen (`DB.loadProof('h:'+id)`). `habitlogs.pf = { <key>: true }` merkt, zu welchen Haken es ein Foto gibt.
- `habitok/{uid}_{day}_{key}`: Bestätigung eines Hakens durch jemand anderen, **nur wenn `habitproofs/<gleiche ID>` existiert** (uid, day, h = '0'–'2' oder 'x0'–'x4', by, byName, ts); wie Nachtragen bis 2 Tage nach dem Tag, Tage der Vorwoche nur bis Montag 14 Uhr; nur der Bestätiger darf löschen (gleiches Fenster), `byName` max. 20 Zeichen
- `players.extraHabits`: bis zu 5 `{ name, target, confirm }`, jederzeit änderbar. `confirm: true` (auch bei den 3 Punkte-Habits, dann im Habit-Fenster änderbar) = Haken zählt nur mit `habitok`.
- `weekly/{week}`: text, kind ('daily'|'count'), target, setBy, setByName, ts (nur create, nicht überschreibbar)
- `tasks/e{etappe}_{uid}`: etappe, text, createdBy, createdByName
- `taskDone/{taskId}_{uid}`: uid, taskId, ts, note, proof (true = Foto in proofs), confirmedBy, confirmedByName, confirmedAt (nur ein anderer Spieler darf bestätigen, nicht nach einer Ablehnung; confirmedAt nur als Serverzeit), rejectedBy, rejectedByName, rejectedAt (Serverzeit), rejectReason (≤ 140; nur ein anderer, solange die Meldung wartet). Melden und neu melden nur mit frischem Foto im selben Batch (`freshProof`). Alte Meldungen ohne Foto bleiben bestätigbar.
- `proofs/{taskDoneId}`: uid, taskId, img (data-URL base64, < 400.000 Zeichen, jpeg/webp/png), w, h, ts (Serverzeit). Nur der Besitzer schreibt/löscht, und nur solange die Meldung nicht bestätigt ist; danach bleibt das Foto. Lesen: alle Mitglieder.
- `teamideas/e{etappe}_{uid}`: etappe, text, kind ('sum'|'count'), per, period ('day'|'week'|'month'), unit, setBy, setByName, ts (create bis zur Ziehung, zurückziehen = delete)
- `teamlogs/{uid}_{day}`: uid, day, etappe, vals `{ <ideaId>: Zahl }` (nur eigene, Nachtragefenster + bis Montag 14 Uhr nach der Etappe)
- `reminderRuns/{kind}_{YYYY-MM-DD}`: nur das Erinnerungs-Skript (Admin), verhindert doppelten Versand

## App-Struktur
Tabs: Heute · Ranking (Woche/Etappe/Gesamt/Kasse) · Challenges (Extra-Aufgaben, Team-Monat inkl. Vorschläge, Challenge-Historie) · Verlauf (Abnahme aller, Wochen-Chronik) · Ich (privat: Ziel-Ring, kg-Diagramm/Tabelle, Saison-Heatmap, Meilensteine) · Regeln. Auf Handy/Tablet hat die untere Leiste 5 Tabs, Regeln sitzt als Knopf „Regeln“ oben rechts neben dem Profil (unter 360 px nur Icon); auf dem Desktop steht alles in der Seitenleiste, dort sind Ich und Verlauf ein Tab „Ich & Verlauf“ (`viewTab()`, `#verlauf` landet dort). Der aktive Tab steht im URL-Hash, per `replaceState`. Profil (Name, Habits + Wochenziele, Pause, Erinnerungen, Einladungscode) als Bottom-Sheet bzw. Seitenpanel. Dialoge (Ausstieg, Einführung) auf dem Desktop mittig (`.modal.mid`).
- **Layout (fluid, kein max-width):** Jeder Tab ist ein `.board` (CSS-Grid). Die Spaltenzahl kommt aus Container Queries auf `.page` (`container: page`): 1 → 2 → 3 → 4 Spalten bei 44/68/92 rem (Heute), Ranking ab 52 rem Liste | Diagramm, Challenges 44/72 rem, Ich & Verlauf 44/72/100 rem. `.pane` = Block/Spalte, `.grp` = Gruppe, die je nach Breite selbst eine Spalte ist oder sich per `display: contents` auflöst; Reihenfolge per `order`. **Desktop (≥ 1025 px, Seitenleiste):** Inhaltsbereich genau `100dvh`, die Seite scrollt nicht, jede Spalte scrollt für sich (`overflow-y: auto`, 10 px Innenrand gegen abgeschnittenes Leuchten). **Handy/Tablet:** Seite scrollt normal, kurzer Inhalt wird bis zum unteren Rand gestreckt. Ab 2 Spalten wächst die letzte Karte jeder Spalte bzw. eine `.fillc`-Karte in die Resthöhe (die Wochenletzter-Karte nicht). Fließtext (Regeln) höchstens ~70 Zeichen pro Spalte, mehrspaltig auf breiten Schirmen; Daten (Raster, Ranking, Tabellen, Diagramme) nutzen die volle Breite und skalieren per `clamp()` mit Container-Einheiten (`cqi`).
- **Heute** = Dashboard: Panes `f` Liveticker, `a` Wiegen + Wochenstand (Platz, 3 Wochenringe, Mini-Ranking, Ziel-Balken bzw. Haltephase) + Wochenletzter, `b` Habit-Raster + Heatmap, `c` Wochen-Challenge + Team-Monat + Meilensteine. Pane `d` = Team-Monat + Meilensteine. Gruppen `gL[gF[f a]]` und `gB[b gR[c d]]`. 1 Spalte: f a b c d (Heatmap/Meilensteine ausgeblendet); 2: [f a] [b c d]; 3: [f a] [b] [c d]; 4: [f] [a] [b] [c d]. Liveticker-Liste auf dem Desktop höchstens 32 % der Höhe (`cqb`), als eigene Spalte voll. Handy quer: Habits direkt nach dem Liveticker. Ausgestiegene sehen statt Wiegen/Raster ihr eingefrorenes Ergebnis.
- **Viele Spieler:** nichts geht von einer festen Spielerzahl aus. Mini-Ranking ab 8 Spielern nur Top 3, du mit Nachbarn, der Letzte (`windowed()`); Chips umbrechend; Diagramme dimmen ab 7 Linien alle außer deiner, Tooltip höchstens 10; Spielerfarben `colorOf()`.
- **Ranking:** Zeile = Platz, Name (+ aktiv, Haltephase, Pause, Streak, Meilensteine), Aufschlüsselung, Punkte. Schmal „30 · 16 · 6“ mit Legende, ab 540px Kartenbreite echte Spalten. Woche: „Pause: …“ unter der Liste. Gesamt: Abschnitt „Ziel erreicht“. Kasse: Spalte „Einsatz zurück“, sobald jemand ausgestiegen ist.
- **Diagramme** (`drawChart`) in echter Pixelgröße (ResizeObserver, Schlüssel Breite × Höhe), Schrift 12px. `.chart.fill` in einer `.fillc`-Karte füllt ab 2 Spalten Breite UND Höhe (CSS setzt `--fill: 1`, SVG absolut), sonst Höhe aus der Breite. Optionen: `zero:false`, `x0`, `area`, `refs`, `hl`. Glow über SVG-Filter `#fx-glow`.
- **Formulare beim Neuzeichnen:** Eingaben landen in `UI.drafts` (Schlüssel `data-draft` oder id, Extra-Habit-Zeilen als Liste `xl:<pre>`), gelöscht erst nach erfolgreichem Speichern (`formSaved(form)`). Karten mit `data-form` bleiben beim Neuzeichnen als Knoten stehen, solange ein Feld darin Fokus hat oder geändert ist (`paint()` → `morph()`), alles drumherum bekommt neue Daten. Blättern innerhalb so einer Karte: `UI.force.add(<data-form>)`. Neue Formulare: Karte mit `data-form`, Felder mit id, nach dem Speichern `formSaved(form)`. Test: `tests/forms.mjs`.
- **Rendern:** `render()` baut `#app` bei jedem Daten-Update neu. Animationen nur gezielt: Seitenwechsel bei Tab-Wechsel (`.page.enter`, Panes steigen gestaffelt auf), Haken-Feder über `TAP`, Ticker-Einträge nur wenn neu, Overlays nur beim Öffnen (`.fresh`). Saisonrückblick wird nach dem Öffnen nicht neu gezeichnet.
- Daten-Schicht: `makeDemoDB` und `makeFirebaseDB` mit identischer Schnittstelle (inkl. register, updatePlayer, saveWeigh(slot, kg, lossPct, player?), finish(fw), addTeamIdea, delTeamIdea, setTeamLog, enablePush, disablePush, pushState). Punkte-Logik in `compute()` (Wochen inkl. Haltephase, Pause, Ausstieg; Team, Streak, Meilensteine), `weekLosers()`, `fees()` (inkl. `refund`), `pot()`, `teamMonth()`, `streakOf()`, `habitsFor()`. Feed: `feedEvents()`, Rückblick: `wrappedData()`.
- Neue Sammlungen werden „optional“ abonniert: Fehlen die Regeln noch, bleibt die App benutzbar.
- **Laden:** Sammlungen erst abonnieren, wenn das eigene Spieler-Dokument auf dem Server liegt (`includeMetadataChanges`, `hasPendingWrites`). Abgelehnte Listener bis zu 6× neu; nach 12 s „Neu laden“-Knopf.
- **Fotos:** `proofs` nie abonnieren, nur einzeln laden (je Foto 1 Lesevorgang, bis ~400 KB). Speicher: Spark hat 1 GiB, bei ~150 KB pro Foto reicht das für Tausende.
- **Lesekosten im Blick behalten:** Jeder App-Start liest alle `habitlogs` (Spieler × Tage). Bei 20 Spielern am Saisonende ~3.400 Dokumente pro Start, das Spark-Limit ist 50.000 Lesevorgänge/Tag. Das wöchentliche Backup liest jedes Dokument einmal (plus eine Abfrage der Unter-Sammlungen pro Dokument). Ab ~8 Spielern Wochen-Dokumente statt Tages-Dokumente erwägen.

## Design
„Apple Fitness trifft Fight Club“: Smartwatch-Datenoptik mit rauer, brutalistischer Kante. Alle Tokens oben in `style.css`.
- **Farben:** OLED-Schwarz `--bg #000`, Karten `#111111` / `#1c1c1e` / `#2c2c2e`. Neon nur mit fester Bedeutung: **Grün `--lime #b6ff3c`** = Habits, erledigt, Hauptaktion, Fokus; **Pink `--pink #ff2d78`** = Waage, Gewicht, eigenes Ziel; **Cyan `--cyan #2de2ff`** = Gruppe (Wochen-Challenge, Team-Monat, Aufgaben). **Blutorange `--blood #ff4a1c`** = Strafen, Warnungen, Wochenletzter, „seit X Tagen still“. Karten tragen ein kleines Quadrat in ihrer Kategoriefarbe (`data-k`). Spielerfarben `--p1…--p10` fest nach Beitritt.
- **Genau ein heller Fokus pro Screen (grün):** Heute = montags die Wiege-Karte (grüner Rahmen + Button), sonst die heutige Spalte im Habit-Raster. Ranking = Platz 1. Pro Karte höchstens ein grüner Button, Nebenaktionen als `.btn.ghost` oder `.link`. Endgültige Aktionen mit Geld (Aussteigen) als `.btn.danger` bzw. `.btn.ghost.danger` in Blutorange. Einzige Ausnahme mit Bewegung: die pulsierende Wochenletzter-Karte.
- **Typo:** Schibsted Grotesk, harte Gewichtskontraste: riesige Zahlen in 900 mit enger Laufweite (Platz, kg-Eingabe, Ring-Mitte, Wrapped), Labels 13 px/700 in Grau. Tabellenziffern für Zahlen; Komma/Punkt per `tn()` schmal halten (die tnum-Variante der Schrift macht sie sehr breit). CSS-Regeln für `span` in Zahl-Containern nur als `>span` schreiben, sonst treffen sie das Komma-`span` von `tn()` (z. B. `.rk .br>span`). Allgemeine Klassennamen nicht doppelt belegen: `p.lead` (Anmeldeseite) vs. `.rk.lead` (Platz 1).
- **Bewegung:** Feder-Kurve `--spring` für Klicks (Haken 0,95 → 1,07 → 1 plus grünes Aufleuchten, Buttons, Tabs), `--out` für Einblenden. Seitenwechsel gleitet in Tab-Richtung, Ringe laufen beim Öffnen voll, Heatmap baut sich diagonal auf. `prefers-reduced-motion` schaltet alles ab.
- Keine Emojis in der UI; Icons als Inline-SVG (24er Raster, 1,5 px Strich) in `I`. Radien 4–8 px, keine Pillen, keine Versalien-Labels.
- Abstände: 4/8er Raster, Karten-Innenabstand `--pad` (12/16/20 px je Breite), Rhythmus `.card>*+*` = 12 px. Media Queries nur noch für die Hülle: 640 (Tablet) und 1025 (Desktop: Seitenleiste 232 px, Inhaltsbereich in Fensterhöhe). Alles innerhalb per Container Queries (siehe Layout), kein max-width.
- Kontrast: alle Textfarben ≥ 4,5:1 auf `#000`, `#111111` und `#1c1c1e` (geprüft). Auf `#2c2c2e` (Hover/aktiv) nur weiße Schrift, Grau und Pink wären dort zu schwach.

## Habits: Extras und Bestätigung (Nov 2026)
- Anzeige heißt überall „Habits“ (früher Gewohnheiten).
- Extra-Habits: eigene Zeilen im Raster unter dem Trenner „Extra, ohne Punkte“, keine Punkte, keine Strafe, keine Erinnerung. Anlegen/ändern/entfernen direkt in der Habit-Karte („+ Extra-Habit“, „Bearbeiten“ → Editor `#hX`, `UI.xEdit`) und weiter im Profil.
- **Feste Plätze:** Haken liegen in `habitlogs.extra[Platz]`, Bestätigungen unter `x<Platz>`. Entfernen setzt nur `off: true` (Platz bleibt), neue Extras hängen hinten an oder nehmen einen entfernten Platz mit `from: <Tag>` (ältere Haken dort zählen nicht; auch wenn der neue Platz schon alte Haken hat). `extraSlots()` (alle, mit `i`, `off`, `from`), `extrasOf()` (aktive), `mergeExtras()` (Editor → Liste). Alte kompakte Listen gelten unverändert (Platz = Index).
- „Gruppe bestätigt“: **Abhaken nur mit Foto** (Fenster `hproof`: Kamera/Galerie, dann „Abhaken“; `tickHabit()`, `DB.setHabit(day, done, extra, { key, img })`), Haken zurück löscht das Foto. Beim Einschalten des Schalters ein Hinweis-Toast. Haken erscheinen gestrichelt, bis jemand anderes in der Karte „Bestätigen“ (Heute) auf „Ansehen“ tippt und im Foto-Fenster bestätigt (alte Haken ohne Foto: „ohne Foto: neu abhaken“); `tickCounts(hl, w, H, uid)` / `extraCounts` zählen nur bestätigte Tage. Demo: Julian bestätigt nach 3 s (`DB.autoConfirm`), Siggi hat ein Extra mit Bestätigung.
- Haltephase: volle Waage-Punkte, solange `lossPct >= Ziel − holdBand` (unter dem Zielgewicht, 1 Prozentpunkt Puffer); Habits bleiben Pflicht, kein Bonus. Karte „Ziel erreicht“ (`goalChoiceCard`) zeigt beide Wege, „Weitermachen“ blendet sie aus (`cdf-goalchoice-<uid>`).
